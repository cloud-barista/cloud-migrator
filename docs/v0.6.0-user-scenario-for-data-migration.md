# Data migration scenarios

> [!IMPORTANT]
> This document describes the **portal/upper-subsystem perspective** of data migration scenarios.
> The scenarios represent the interaction between the user, the web console (Butterfly), and backend subsystems (Beetle) during the full data migration workflow.

> [!NOTE]
> Data migration transfers actual data (files or objects) between a source endpoint and a target endpoint.
> Both source and destination must be **remote** endpoints (SSH filesystem or object storage).
> Local filesystem access is not permitted for security reasons.
>
> This scenario assumes the target object storage buckets are already created via the object storage migration workflow.
> Refer to [v0.6.0-user-scenario-for-object-storage-migration.md](./v0.6.0-user-scenario-for-object-storage-migration.md) for the object storage migration scenario.

> [!NOTE]
> **Namespace (nsId):** All migration APIs require a namespace ID (`nsId`). Use the same namespace selected during the object storage migration workflow. The migrated object storage list is scoped to this `nsId`.

## Login

- Participants: Butterfly

> [!NOTE]
>
> - The user logs in to the Cloud-Migrator web console.
> - Key flow:
>   - --> User accesses the web console
>   - --> Login page is displayed
>   - --> User enters credentials and they are validated
>   - --> User is redirected to the dashboard

```mermaid
sequenceDiagram
    participant User as "User"
    participant Browser as "Web Console"
    participant WebServer as "Butterfly"

    %% Step 1: Access the Cloud-Migrator Web Console
    User->>Browser: Access the Cloud-Migrator Web Console
    activate Browser
    Browser->>WebServer: Request a view to login
    activate WebServer
    WebServer-->>Browser: Return the view to login
    deactivate WebServer
    Browser-->>User: Display login page
    deactivate Browser

    %% Step 2: Enter login credentials
    User->>Browser: Enter login credentials
    activate Browser
    Browser->>WebServer: Send login credentials (Username, Password)
    activate WebServer
    WebServer-->>Browser: Validate and return the dashboard page
    deactivate WebServer
    Browser-->>User: Display dashboard page
    deactivate Browser
```

## Execute data migration

- Participants: Butterfly, Damselfly, Beetle, Tumblebug, Source Storage, Target Storage

> [!NOTE]
>
> - The data migration view loads source models (Damselfly) and migrated object storages (Beetle) simultaneously when the page opens.
> - Source `path` is auto-filled from the registered model; access credentials are **entered temporarily by the user at migration time and are never persisted**.
> - Destination is **fully auto-filled** from the migrated object storage info (tumblebug accessType).
> - The portal automatically obtains a one-time encryption key, encrypts the temporarily entered credentials client-side, and sends the encrypted request to Beetle.
> - This is an **asynchronous** operation — Beetle returns `reqId` immediately and runs the transfer in the background.
> - Key flow:
>   - --> Page loads source model list (Damselfly) and migrated OS list (Beetle) in parallel
>   - --> User selects source model → `bucketName` auto-fills as `source.path`
>   - --> User temporarily enters source access credentials (not stored anywhere)
>   - --> User selects destination OS → all destination fields auto-filled (tumblebug)
>   - --> User selects transfer strategy and optionally sets filter / pre/post commands
>   - --> Portal gets one-time encryption key from Beetle → encrypts credentials client-side
>   - --> Portal assembles `DataMigrationModel` and calls `POST /migration/data`
>   - --> Beetle returns `202 Accepted` with `reqId`

```mermaid
sequenceDiagram
    participant User as "User"
    participant Browser as "Web Console"
    participant Butterfly as "Butterfly"
    participant Damselfly as "Damselfly"
    participant Beetle as "Beetle"
    participant Tumblebug as "Tumblebug"
    participant SrcStorage as "Source Storage"
    participant DstStorage as "Target Storage"

    %% Step 0: Page load — fetch source models and migrated OS list in parallel
    User->>Browser: Access the Data Migration view
    activate Browser
    Browser->>Butterfly: Request the Data Migration view
    activate Butterfly
    par Load source object storage models from Damselfly
        Butterfly->>Damselfly: API call GET /damselfly/sourceObjectStorageModel
        activate Damselfly
        Damselfly-->>Butterfly: Return source model list
        deactivate Damselfly
    and Load migrated object storage list from Beetle
        Butterfly->>Beetle: API call GET /beetle/migration/middleware/ns/{nsId}/objectStorage
        activate Beetle
        Beetle->>Tumblebug: API call GET /tumblebug/ns/{nsId}/resources/objectStorage
        activate Tumblebug
        Tumblebug-->>Beetle: Return list
        deactivate Tumblebug
        Beetle-->>Butterfly: Return MigratedObjectStorageListResponse
        deactivate Beetle
    end
    Butterfly-->>Browser: Respond with the view
    deactivate Butterfly
    Browser-->>User: Display Data Migration form (source model list + destination OS list)
    deactivate Browser

    %% Step 1: Select source model → auto-fill source path
    User->>Browser: Select a source model from the list
    activate Browser
    Browser->>Butterfly: Request source model detail by model ID
    activate Butterfly
    Butterfly->>Damselfly: API call GET /damselfly/sourceObjectStorageModel/{modelId}
    activate Damselfly
    Damselfly-->>Butterfly: Return SourceObjectStorage (bucketName, size, objectCount, etc.)
    deactivate Damselfly
    Butterfly-->>Browser: Respond with source model detail
    deactivate Butterfly
    Browser-->>User: Auto-fill source fields
    Note over Browser,User: Auto-filled from model:<br/>source.storageType = "objectstorage"<br/>source.path = bucketName
    deactivate Browser

    %% Step 2: User temporarily enters source credentials (not stored)
    User->>Browser: Select source access type and enter credentials
    activate Browser
    alt Source is S3-compatible object storage
        Note over Browser,User: Temporarily entered by user — never persisted:<br/>accessType: "minio"<br/>endpoint, accessKeyId, secretAccessKey, region, useSSL
    else Source is SSH filesystem (e.g., source on-premise server)
        Note over Browser,User: Temporarily entered by user — never persisted:<br/>accessType: "ssh"<br/>host, port (default 22), username<br/>privateKey (PEM content) or privateKeyPath
    end
    Browser-->>User: Reflect credentials in the form (memory only)
    deactivate Browser

    %% Step 3: Select destination OS → auto-fill all destination fields
    User->>Browser: Select a destination bucket from the migrated OS list
    activate Browser
    Browser->>Butterfly: Request detail of selected object storage (osId)
    activate Butterfly
    Butterfly->>Beetle: API call GET /beetle/migration/middleware/ns/{nsId}/objectStorage/{osId}
    activate Beetle
    Beetle->>Tumblebug: API call GET /tumblebug/ns/{nsId}/resources/objectStorage/{osId}
    activate Tumblebug
    Tumblebug-->>Beetle: Return bucket detail (ObjectStorageInfo)
    deactivate Tumblebug
    Beetle-->>Butterfly: Return MigratedObjectStorageInfo
    deactivate Beetle
    Butterfly-->>Browser: Respond with bucket detail
    deactivate Butterfly
    Browser-->>User: Auto-fill all destination fields
    Note over Browser,User: Auto-filled — no user input required:<br/>destination.storageType = "objectstorage"<br/>destination.path = name (bucketName)<br/>destination.objectStorage.accessType = "tumblebug"<br/>destination.objectStorage.tumblebug.endpoint = (system config)<br/>destination.objectStorage.tumblebug.nsId = nsId<br/>destination.objectStorage.tumblebug.osId = id (osId)
    deactivate Browser

    %% Step 4: Set optional parameters
    User->>Browser: Select transfer strategy and set optional parameters
    activate Browser
    Note over Browser,User: strategy: "auto" | "direct" | "relay" (default: auto)<br/>filter.include / filter.exclude (optional)<br/>source.preCmd / destination.postCmd (optional)
    Browser-->>User: Update form
    deactivate Browser

    %% Step 5: Portal obtains encryption key and encrypts credentials client-side
    User->>Browser: Click "Start Data Migration"
    activate Browser
    Browser->>Butterfly: Request one-time encryption public key
    activate Butterfly
    Butterfly->>Beetle: API call GET /beetle/migration/data/encryptionKey
    activate Beetle
    Beetle->>Beetle: Generate one-time RSA key pair
    Note over Beetle: Validity: 30 min / Auto-invalidated after use<br/>Algorithm: RSA-OAEP-256 + AES-256-GCM
    Beetle-->>Butterfly: Return PublicKeyBundle (keyId, publicKey, expiresAt)
    deactivate Beetle
    Butterfly-->>Browser: Respond with public key bundle
    deactivate Butterfly
    Browser->>Browser: Encrypt temporarily entered credentials using the public key
    Note over Browser: Encrypted fields: accessKeyId, secretAccessKey<br/>(credentials are cleared from memory after encryption)

    %% Step 6: Assemble DataMigrationModel and call migration API
    Browser->>Butterfly: Request to execute data migration
    activate Butterfly
    Butterfly->>Beetle: API call POST /beetle/migration/data (X-Request-Id header)
    Note over Butterfly,Beetle: Request body (DataMigrationModel):<br/>source: { storageType, path, objectStorage: { accessType, minio: {encrypted} }, filter, preCmd }<br/>destination: { storageType, path, objectStorage: { accessType: "tumblebug", tumblebug: {endpoint, nsId, osId} }, postCmd }<br/>strategy: "auto" | "direct" | "relay"<br/>encryptionKeyId: keyId (from Step 5)
    activate Beetle
    Beetle->>Beetle: Decrypt credentials using stored private key
    Note over Beetle: One-time key deleted after decryption
    Beetle->>Beetle: Validate endpoints (both must be remote)
    Beetle->>Beetle: Start background data transfer
    Beetle-->>Butterfly: Return 202 Accepted with reqId (AsyncJobResponse)
    deactivate Beetle
    Butterfly-->>Browser: Respond with reqId
    deactivate Butterfly
    Browser-->>User: Display "Migration started" with reqId
    deactivate Browser

    %% Step 7: Background transfer (async)
    Note over Beetle,DstStorage: Background transfer in progress (async)
    Beetle->>SrcStorage: Connect and read source data
    activate SrcStorage
    SrcStorage-->>Beetle: Stream source data
    deactivate SrcStorage
    Beetle->>DstStorage: Write data to destination
    activate DstStorage
    DstStorage-->>Beetle: Acknowledge write
    deactivate DstStorage
    Beetle->>Beetle: Update request status (Handling → Success/Error)
```

## Check migration status

- Participants: Butterfly, Beetle

> [!NOTE]
>
> - After submitting the migration request, the portal periodically checks the status using the reqId.
> - Key flow:
>   - --> Portal periodically calls the status endpoint with the reqId
>   - --> Status transitions from "Handling" to "Success" or "Error"
>   - --> Portal displays progress and final result to the user

```mermaid
sequenceDiagram
    participant User as "User"
    participant Browser as "Web Console"
    participant Butterfly as "Butterfly"
    participant Beetle as "Beetle"

    %% Step 1: Poll status
    loop Poll until status is Success or Error
        Browser->>Butterfly: Poll migration status
        activate Butterfly
        Butterfly->>Beetle: API call GET /beetle/request/{reqId}
        activate Beetle
        Beetle-->>Butterfly: Return current status
        Note over Beetle,Butterfly: Status: "Handling" | "Success" | "Error"
        deactivate Beetle
        Butterfly-->>Browser: Respond with status
        deactivate Butterfly
        Browser-->>User: Update progress display
    end

    %% Step 2: Handle final result
    alt Status is Success
        Browser-->>User: Display "Data migration completed successfully"
    else Status is Error
        Browser-->>User: Display error message and details
        Note over Browser,User: User can retry or check logs
    end

    %% Step 3: View all requests (optional)
    opt View all migration requests
        User->>Browser: Click "View All Migration Requests"
        activate Browser
        Browser->>Butterfly: Request all migration request records
        activate Butterfly
        Butterfly->>Beetle: API call GET /beetle/requests
        activate Beetle
        Beetle-->>Butterfly: Return all request records
        deactivate Beetle
        Butterfly-->>Browser: Respond with all records
        deactivate Butterfly
        Browser-->>User: Display migration request history
        deactivate Browser
    end
```

## Verify migrated data (optional)

- Participants: Butterfly, Damselfly, Beetle, Tumblebug

> [!NOTE]
>
> - This step is **optional but recommended**. The migration itself is complete once the async transfer status reaches "Success".
> - The user can verify that data was transferred correctly to the target object storage at any time after migration completes.
> - The source metrics (objectCount, totalSizeBytes) for comparison are fetched from the Damselfly source model.
> - Key flow:
>   - --> Query object list in the target bucket
>   - --> Fetch source model from Damselfly to obtain baseline objectCount and totalSizeBytes
>   - --> Display side-by-side comparison of source vs. migrated counts and sizes
>   - --> Optionally check individual object metadata
>   - --> Optionally clean up unwanted objects

```mermaid
sequenceDiagram
    participant User as "User"
    participant Browser as "Web Console"
    participant Butterfly as "Butterfly"
    participant Damselfly as "Damselfly"
    participant Beetle as "Beetle"
    participant Tumblebug as "Tumblebug"

    %% Step 1: List objects in the target bucket and fetch source model in parallel
    User->>Browser: Click "Verify Migrated Data" for the target bucket (osId)
    activate Browser
    Browser->>Butterfly: Request object list and source model
    activate Butterfly
    par Query target object list from Beetle
        Butterfly->>Beetle: API call GET /beetle/migration/middleware/ns/{nsId}/objectStorage/{osId}/object
        activate Beetle
        Beetle->>Tumblebug: API call GET /tumblebug/ns/{nsId}/resources/objectStorage/{osId}/object
        activate Tumblebug
        Tumblebug-->>Beetle: Return object list
        deactivate Tumblebug
        Beetle-->>Butterfly: Return object list (StorageObjectListResponse)
        Note over Beetle,Butterfly: count, objects: [ { key, size, lastModified, storageClass, eTag } ]
        deactivate Beetle
    and Fetch source model from Damselfly
        Butterfly->>Damselfly: API call GET /damselfly/sourceObjectStorageModel/{modelId}
        activate Damselfly
        Damselfly-->>Butterfly: Return SourceObjectStorage (objectCount, totalSizeBytes, bucketName)
        deactivate Damselfly
    end
    Butterfly-->>Browser: Respond with object list + source model
    deactivate Butterfly
    Browser-->>User: Display object list with count and total size
    deactivate Browser

    %% Step 2: Compare with source
    User->>Browser: Compare object count and size with source bucket info
    activate Browser
    Note over Browser,User: Side-by-side comparison using Damselfly source model:<br/>Source objectCount (from model) vs. migrated count (from Beetle)<br/>Source totalSizeBytes (from model) vs. migrated total size (from Beetle)
    Browser-->>User: Show comparison result (match / mismatch)
    deactivate Browser

    %% Step 3: Check individual object metadata (optional)
    opt Check specific object metadata
        User->>Browser: Select an object and click "Check Metadata"
        activate Browser
        Browser->>Butterfly: Request object metadata
        activate Butterfly
        Butterfly->>Beetle: API call HEAD /beetle/migration/middleware/ns/{nsId}/objectStorage/{osId}/object/{objectKey}
        activate Beetle
        Beetle->>Tumblebug: API call HEAD /tumblebug/ns/{nsId}/resources/objectStorage/{osId}/object/{objectKey}
        activate Tumblebug
        Tumblebug-->>Beetle: Return object metadata in response headers (key, size, eTag, lastModified)
        deactivate Tumblebug
        Beetle-->>Butterfly: Return metadata (StorageObjectMetadata)
        deactivate Beetle
        Butterfly-->>Browser: Respond with metadata
        deactivate Butterfly
        Browser-->>User: Display key, size, lastModified, eTag, storageClass
        deactivate Browser
    end

    %% Step 4: Clean up unwanted objects (optional)
    opt Delete specific objects
        User->>Browser: Select object and click "Delete"
        activate Browser
        Browser->>Butterfly: Request object deletion
        activate Butterfly
        Butterfly->>Beetle: API call DELETE /beetle/migration/middleware/ns/{nsId}/objectStorage/{osId}/object/{objectKey}
        activate Beetle
        Beetle->>Tumblebug: API call DELETE /tumblebug/ns/{nsId}/resources/objectStorage/{osId}/object/{objectKey}
        activate Tumblebug
        Tumblebug-->>Beetle: Return deletion result
        deactivate Tumblebug
        Beetle-->>Butterfly: Return deletion result
        deactivate Beetle
        Butterfly-->>Browser: Respond with deletion confirmation
        deactivate Butterfly
        Browser-->>User: Display deletion confirmation
        deactivate Browser
    end
```
